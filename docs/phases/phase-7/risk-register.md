# Phase 7 — Risk Register

**Phase:** 7 · **Owner:** orchestrator
**Document status:** continues the single project-wide sequence; Phase 6 closed at `RISK-109`, so Phase 7
opens at `RISK-110`. Each entry is risk, the mitigation actually in the tree at `d1fe1a0`, and the residue the
mitigation does not remove.

| id | risk | likelihood / impact | mitigation in the tree | residue |
|---|---|---|---|---|
| RISK-110 | A resolved protocol is treated as a supported/verified device (the "known device ≠ supported device" failure) | High / High | Resolution yields a *candidate*; `ProtocolResolution.isActionable` is true only for a single `RESOLVED` candidate; the registry ships empty so the shipped answer is `UNKNOWN`; verification is gated by `VerificationLevel` (a control needs ≥ `LAB_TESTED`, a support claim `HARDWARE_VERIFIED`) | The gate is advisory to a future capability/UI layer; only the deferred hardware session can raise a rung, and nothing here lets a caller fake it |
| RISK-111 | A brand name in a display string is used to select a protocol (the defect every protocol engine tempts you into) | Med / High | Resolution matches exact `protocolCandidates` and evidence only; there is no name/fuzzy/brand match anywhere in `core.protocol`; ADR-P7-006 records the prohibition; `PROTO-ID-001` from Phase 5 | None for this phase's resolver; a later phase must not add name-matching to it — this file + `ProtocolResolverTest` are the tripwire |
| RISK-112 | An empty or placeholder registry is mistaken for "the framework is broken" and filled with an invented vendor protocol | High / High | ADR-P7-010 states emptiness as the decision (ADR-P1-013/ADR-P5-006 precedent); `PhaseSevenScopeTest.theShippedRegistryHoldsNoProtocol` + Phase 1's `ProtocolRegistryTest` fail the build if a default record appears | The guard proves the *default* is empty, not that a later registered record's facts are real — evidence review remains human |
| RISK-113 | A timed-out command is blindly re-sent, compounding a side effect nobody observed | Med / High | `execute` sends once; `EffectClass` forbids a write retry budget at construction; a timeout is `RETRY_AFTER_REREAD`, not a re-send; `ProtocolSessionTest.aCommandIsSentExactlyOnceEvenWhenTheReplyFails` | Re-read-then-decide is a later phase's flow; this phase guarantees the *transport of the command* is single-shot |
| RISK-114 | Requested state is displayed or stored as device-confirmed state | Med / High | `ProtocolEvent` carries only device-reported values; a command's requested value lives in the command/response; `acknowledged` is delivery-level and documented; types make conflation awkward | A careless UI could still echo an ack as a state; no UI exists in Phase 7 (prompt §17) |
| RISK-115 | The session is marked READY without a real initialization success (premature readiness) | Med / High | `READY` is reachable only from `INITIALIZING` in the transition table; `ProtocolStateTest` + `ProtocolSessionTest` lock both | Enforced by the state machine and a concrete session's discipline; a rogue `MutableStateFlow` write is outside the type (the Phase 1 copy-bypass caveat) |
| RISK-116 | A production fake session is added to `:core` to make the framework "look used" | Med / High | `PhaseSevenScopeTest.noProductionSourceImplementsTheRuntimeProtocolInterfaces` fails if any `src/main` type implements the session/adapter; scripted sessions are test-only | Relies on the marker-string scan; a differently-phrased implementer could evade it — the architecture review + `DependencyDirectionTest` are the backstop |
| RISK-117 | The protocol layer reaches `android.bluetooth` or a transport concrete, breaking platform-independence | Low / High | Layer map forbids L4→framework; `PhaseSevenScopeTest.theProtocolPackageImportsNoAndroidClass` scans for `android.` imports; the adapter boundary is a `:core` interface | None in Phase 7; a later binding must live in the platform module behind the seam |
| RISK-118 | Forking §8's verification ladder or §11's `UNKNOWN_SIDE_EFFECT` creates a second vocabulary that drifts from the master's | Med / High | ADR-P7-003/004 reuse `VerificationLevel`/`EffectClass` and record the prompt's names as aliases; no new enum | A future reader must honour the reconciliation; the ADR + `specs.md` §2/§6 are the pointer |
| RISK-119 | Malformed device bytes crash the engine or become a fabricated value | Med / Med | Responses are produced by `ProtocolParser` (a failure, not a half object); `ProtocolResponse` keeps null≠empty; payloads bounded; no raw bytes in `toString` | Real parsing edge cases need a real protocol; until then only the contract is exercised |
| RISK-120 | An event stream grows unbounded or leaks a collector | Low / Med | `replay = 0` + bounded buffer + `DROP_OLDEST`, cancellation-safe collector, the `StateFlow` is the truth (Phase 4 pattern) | The concrete session's collector hygiene is a later-phase obligation; the contract states it |
| RISK-121 | No hardware claim because JVM tests pass | High / Med | Standing directive + TST-HW-003 cap everything at `IMPLEMENTED`; device verification `NOT RUN`; the empty registry means no protocol is claimed for any device | Inherent to a JVM-only, protocol-less phase; closes only in the deferred device session (RISK-097/099 continue) |
