# Phase 4 — Test Plan

**Phase:** 4 — Device Session & Lifecycle Management · **Scope id:** `P4` · **Owner agent:** testing-and-risk workstream / orchestrator as integration owner
**Instantiates:** `docs/phases/phase-0/testing-governance.md` — tiers T1–T8 (§2.1), the mandatory eight-field record (TST-REC-001), the id grammar (TST-REC-002), the `REQ` ↔ `TEST` ↔ tier ↔ level matrix (TST-REC-006), the mocking ceiling (TST-MOCK-001, TST-MOCK-006), the no-relaxation rule (TST-GOV-001), the regression discipline (TST-REG-005, TST-REG-006), the record-what-did-not-run rule (TST-REC-005) and the per-device report form that is the only way support may ever be claimed (TST-HW-003) — using `docs/templates/test-plan-template.md`. Phase 4 adds no rule and relaxes none; where this file is stricter than governance it says so in §1.3 and why.
**ID discipline.** Phase 4 prompt §19 seeds test obligations as prose bullets under seven headings ("Session creation / Session updates / Disconnect / Reconnect / Multiple devices / Concurrency / Architecture") with no ids, exactly as Phases 1, 2 and 3 did; TST-REC-002 fixes the canonical grammar as `TEST-<SCOPE>-<NNN>`, so the seeds are mapped onto `TEST-P4-<NNN>` **once, here**, and never in the `OB-P4-…` form the prompt's neighbouring sections use for requirements. Ids are allocated monotonically from `001`, never reused, never renumbered, and a retired id keeps its number with the reason recorded. `001` … `014` are **executing records** (one per cluster, plus the build gate and the never-run instrumented suite); `015` … `031` are allocated to **gaps** — obligations §19 or §14 or §20 names that nothing executes — so that every unmet bullet has a permanent address. A gap id is a record of something NOT RUN and is never a passing test (TST-REC-005). Two Phase 3 gap ids changed state in this phase and are reported in §7 with that status rather than deleted: `TEST-P3-027` is **closed** at the session layer and `TEST-P3-044` is **narrowed**. Nothing in this file closes a Phase 4 gap: every one of `015` … `031` was found by reading the sources and the fixtures against the prompt, and the two that a device cannot be blamed for (`016`, `026`) are the ones that sting.
**Record shape.** One record per executing cluster. Every method name below was copied from an `@Test` on disk and cross-checked against the `testcase name` attribute in the executed JUnit XML for its class, so the cluster counts sum to the measured totals in §1.1. No name in this file is paraphrased, inferred from a requirement, or quoted from a plan written before the file existed.
**Mocked versus physical.** **MOCKED ENVIRONMENT (TST-MOCK-006).** All 584 distinct executed JVM cases named in this plan — Phase 4's own 61 and the 523 they re-run beside them — are JVM tests against scripted seams. The instrumented suite in `platform/android/src/androidTest/` is **unchanged by Phase 4, still compiles, and still has never been executed**; there is no `adb` target attached, and ADR-P3-014's deferral carries into this phase untouched. §9 is that deferral, written as an ordered instruction, and it reports no result. **No test in this file touched a radio, an adapter, a phone, an emulator, a headset or a Bluetooth announcement, and no test in this file handed the engine a projection a device produced** — the input to every Phase 4 case is a `ConnectedDeviceSnapshot` a test built by hand, whose paired census is empty in every one of them (§8, `TEST-P4-026`). `HARDWARE_VERIFIED` appears nowhere in this file and `IMPLEMENTED` is the highest level any of it justifies.

### 1.3 Evidence ceiling — what a green suite here is worth

Per `testing-governance.md` §2.1, a T1 pass justifies at most **`IMPLEMENTED`**. Every executed cluster in §3 is T1, so **the ceiling for the whole of Phase 4's test evidence is `IMPLEMENTED`**, exactly as ADR-P4-012 decided before the tests were written (ADR-P4-012, `docs/phases/phase-4/decisions.md:343-368`). Therefore:

- nothing here justifies `LAB_TESTED`, `HARDWARE_VERIFIED` or `PERSISTENCE_VERIFIED` (TST-MOCK-001). ADR-P4-012 pre-refuses the inflation route this phase was tempted by: "Testing against Robolectric or an emulated adapter … would raise the apparent tier without raising the real one", and it also refuses claiming **T3** for the harness — the engine's input is a value, not a faked platform-Bluetooth boundary behind the transport abstraction, so TST-TIER-002's T3 condition is unmet and the tier stays T1.
- **persistence is not merely untested, it is refused by design.** ADR-P4-010 makes `SessionClassification.TEMPORARY` the only classification the engine can produce (`everySessionThisEngineMakesIsTemporary`, `beingObservedNeverPromotesASessionIntoASavedRecord`), so no Phase 4 claim can ever reach T5 and no `PERSISTENCE_VERIFIED` row exists to be faked. A session surviving process death is a design "no" (`docs/phases/phase-4/decisions.md:357`), not a gap.
- nothing here is evidence that any phone, adapter, OEM build or headset does or does not expose anything (TST-GOV-004, TST-HW-004). The words "the platform reports" in every record below mean "**the test handed the engine a record that says the platform reported**"; `DeviceObservation.reported` is the factory (`:510-519` of the engine test's helper) and nothing between it and a radio was exercised.
- the instrumented suite earns **no level at all** — not `INFERRED`, not `IMPLEMENTED` — because it has not run, and Phase 4 added no case to it (§3.14, TST-FAIL-001 row 5).
- no capability moves above `UNKNOWN` anywhere in this phase, and `AndroidPlatformCapabilityProvider`'s evidence tiers were not touched (they remain capped at `INFERRED` by ADR-P2-008/ADR-P2-017 and are still asserted as such by `nothingIsClaimedUsableBecauseNoRadioWasOpened`).

**`UNKNOWN` is never collapsed — and Phase 4 is where that rule gets a third layer.** Master §53 and ADR-P0-016 say absence of information is `UNKNOWN`, never `false`, `0`, `DISCONNECTED` or `UNSUPPORTED`. Phase 3 proved the projection cannot lie about a device; Phase 4's job was to prove the session layer cannot read the projection as if it had. The methods that hold that line, by name — `aRefusedRoundKeepsEverySessionAndCarriesItsReason`, `absenceFromAnUnansweredRoundWithdrawsNothing`, `aRefusalIsNotTheSameSentenceAsAnEmptyCensus`, `aDeviceAbsentFromACompleteUnionIsReportedDisconnectedNotDeleted`, `aFirstSightingOfAnUnconnectedDeviceOpensNoSession`, `aPhoneWhoseRadioWentQuietMakesTrackedDevicesUnavailableNotGone`, `aLinkOnTheWayOutIsNeverReadAsADisconnect`, `aBondedDeviceWithNoLinkReadingIsPairedAndNotConnected`, `anEngineWithoutAClockPublishesNullTimesAndNeverZero`, `aMoveTheTransitionTableRefusesIsRecordedAndTheHeldStateKept`, `anExplicitStopClearsTheStoreAndSaysItStoppedRatherThanFoundNothing`, `aStoppedObservationEndsSessionsWithoutClaimingADisconnect`, `anEmptyListIsOnlyEverAFindingUnderACompletedUnion`, `observationStatusPrecedenceKeepsTheFourCasesExclusive`, `aConnectionMoveThatTheTableRefusesReturnsAFailureAndLeavesTheRecordAlone`, `terminationReasonsDescribeEngineDecisionsAndNeverADeviceAct`, `noSessionTypeCanClaimVerificationBeyondWhatThePhaseHas`, `aSessionCarriesNoEvidenceThisPhaseDoesNotHave` — encode it as `SessionObservationStatus.isEmptyMeaningful`, which is `this is Confirmed && unionComplete` and nothing else (`SessionObservationStatus.kt:72-73`), so an empty session list is a census only under a completed union that answered.

**Two absences in main source that the tests do not repair, recorded rather than smoothed.** First, ADR-P4-009's stale-input rule is a **hierarchy of authority** ("a completed census outranks a single-device event even if the event carries a later `observedAtEpochMillis`") and the engine implements no such comparison: the type `ObservationArrival` appears nowhere in `core/session` — the area's only match for the word `arrival` is prose about event kinds at `DeviceSessionEvent.kt:12` — and `DeviceState.applyIfNewer` (`DeviceState.kt:138`) is called by no production path anywhere in the repository, only by `DeviceStateTest` at the type level (`:124`, `:131`, `:139`, `:147`). So the rule is neither enforced nor tested against an out-of-order source: `TEST-P4-018`. Second, `TrackedDeviceSession.terminated(reason, at)` (`:108-109`) and `isLive` (`:61-62`) have **no caller and no reader** anywhere: the engine ends a session by leaving it out of the new list and publishing a `SessionEnded` event, so `termination` is null on every session any test ever saw and `isLive` is true by construction. Nothing pins that, which is `TEST-P4-028` — the honest description of the type is that it carries a field no path fills.

## 9. Deferred physical validation — a numbered instruction to a future session, **not a result**

**Nothing in this section is a claim.** It is prompt §19's deferral ("Physical-device verification remains deferred to the final testing stage. … Do not report unexecuted device tests as passed"), written as a script for a session that has not happened. ADR-P3-014 deferred the device work to the end of the project and ADR-P4-012 inherits that deferral unchanged; "deferred" is a schedule, not an outcome. **Every step below is `NOT RUN` as of this document, and every claim it would settle is `UNKNOWN`.**

Perform it only under `docs/security/device-access-policy.md` (§"Phase 3: instrumented verification, authorised and bounded", `:88-102`): the phone is a personal device; only `com.omnibuds.android`'s own `androidTest` APK may be installed; **no permission may be granted by shell command without the user's explicit say-so at the time**; no `dumpsys bluetooth_manager`; no log or result file may carry a device name or address, because instrumented output leaves the phone through logcat and through the XML in this repository's build directories — a rule Phase 4's redaction tests (§3.11) can only pretend to hold from the JVM side. **Phase 4's own steps, in order.**

1. Attach the user's handset, confirm `adb devices -l` shows it, and note model, Android version, `SDK_INT`, OEM build and the **installed application's own `targetSdkVersion`** before trusting any other measurement (Phase 3's step 1; `TEST-P2-027` still open).
