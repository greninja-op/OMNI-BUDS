# Phase 8 — Risk Register

**Phase:** 8 · **Owner:** orchestrator
**Document status:** continues the single project-wide sequence; Phase 7 closed at `RISK-121`, so Phase 8 opens
at `RISK-122`. Each entry is the risk, the mitigation actually present in the tree at `968adb4`, and the
residue the mitigation does not remove.

| id | risk | likelihood / impact | mitigation in the tree | residue |
|---|---|---|---|---|
| RISK-122 | A parallel capability model (`CapabilityId`/`CapabilitySet`/four §7 enums) is forked from Phase 1 and drifts | High / High | ADR-P8-001 reuses `FeatureId`/`FeatureCapability`/`DeviceCapabilities`/`CapabilityState`; the snapshot *wraps* `DeviceCapabilities`; `DeviceCapabilitiesTest`/`FeatureCapabilityTest` now double as regression guards | A future reader must keep honouring the reconciliation; the ADR + audit §2 are the pointer, not a compile-time block |
| RISK-123 | "Unavailable" is rendered as "unsupported" (the founding-principle failure) | High / High | Availability is a separate `Map` axis; `FeatureCapability` is never widened; `CapabilitySnapshotTest.supportedAndUnavailableAreIndependentAxesAndNeitherMeansUnsupported` + engine `.aBlockedFeatureBecomesUnavailableButStaysSupported` assert support survives gating | Enforced at the model; a careless future UI could still collapse them — the UI-readiness contract (§16/REQ-025) is the tripwire |
| RISK-124 | "Not discovered" is treated as a negative (unknown → unsupported) | High / High | A failed read leaves `UNKNOWN`; `stateOf` misses read `UNKNOWN`; `aFailedReadIsIsolatedAndKeepsThatFeatureUnknownNotUnsupported` + `anUnresolvedProtocolSurfaces...` assert a failure is never `UNSUPPORTED`; unknown prerequisite → `UNKNOWN_PREREQUISITE`, not blocking | None in core; the deferred real protocol's "no such descriptor" path must be coded as a genuine `UNSUPPORTED`, which needs a device |
| RISK-125 | Weak/inferred evidence is promoted to a device claim (marketing text or an unrun parser as `HARDWARE_VERIFIED`) | Med / High | `CapabilityEvidence.init` refuses `INFERRED_MODEL`/`UNKNOWN_OR_INCOMPLETE` above `INFERRED`; `FeatureCapability.init` floors persistence rungs; ceiling `IMPLEMENTED` (ADR-P8-003) | The ceiling is only as honest as the `kind` a caller labels evidence with; no real evidence source ships yet |
| RISK-126 | A weak later read silently overwrites a stronger established capability | Med / High | Reads fold through `DeviceCapabilities.mergedWith` (evidence ladder); `aWeakSecondReadCannotOverwriteAnEstablishedStrongerOne` | A same-rung tie keeps the receiver wholesale by design; genuine cross-source ties need a later reconciliation policy |
| RISK-127 | Contradictory evidence is averaged or one side dropped | Med / High | Both readings are kept; disagreement surfaces as `UnresolvedConflict(feature, kinds)`; `.twoDisagreeingReadsAreSurfacedAsAnUnresolvedConflictNotResolvedSilently`; no numeric confidence (ADR-P5-004) | Surfacing is not resolution — a human/later phase must settle real conflicts; a single read cannot fabricate one |
| RISK-128 | A malformed device response crashes the pass or becomes a fabricated value | Med / High | An untrusted record about the wrong feature is refused as `PartialFailure(INVALID_STATE)`, not filed and not thrown; `aMislabeledReadBecomesAMalformedFailureAndCannotCrashThePass` | Only identity-mismatch is guarded; byte-level malformation has no parser yet and is `NOT RUN` |
| RISK-129 | A dependency edge auto-enables or back-infers a prerequisite's support | Med / High | `DependencyValidator` is pure (returns a report, mutates nothing); validates only observed state; `.validatingNeverEnablesAPrerequisiteNorMutatesCapabilities`; a dependent that disagrees with a missing prereq is surfaced, not repaired | Blocking is availability-only; whether a `READ_ONLY` prerequisite should gate a controllable dependent is a later protocol-governance decision |
| RISK-130 | A dependency cycle loops forever or is quietly broken by dropping an edge | Low / High | Sorted-order DFS reports cycles once; members become `CYCLE` and are blocked, never edge-dropped; `CapabilityDependency` refuses a self-edge; `.aDependencyCycleIsReportedAndItsMembersAreNotOffered` + `.cycleDiscoveryIsDeterministicForTheSameGraph` | The DFS is recursive; bounded by a protocol's small feature set, so depth is safe here — an unbounded caller-supplied graph would need a cap |
| RISK-131 | The L2 engine is tempted to import the protocol layer to "just read a device" | Med / High | ADR-P8-005 hands the engine a `CapabilityDiscoverySource`; `PhaseEightScopeTest.theCapabilityAreaImportsNothingUpward` + `DependencyDirectionTest` fail the build on an L2→L4/L3 edge | The real `ProtocolSession → source` adapter is still to be written at L3/L4; keeping it out of `capability` is the next phase's discipline |
| RISK-132 | Discovery is non-deterministic, so snapshots are uncomparable and merge sites ungreppable | Med / Med | Features read in sorted identity order; snapshot collections ordered; `mergedWith` deterministic; `featureOrderFromTheSourceDoesNotChangeTheSnapshot` asserts whole-snapshot equality across source orders | Sorting keys on `qualifiedName` string order; a later locale/collation change could alter it — the pinned test is the tripwire |
| RISK-133 | A production fake `CapabilityDiscoverySource` is added to `:core` to make the engine "look used" | Med / High | `PhaseEightScopeTest.noProductionSourceImplementsTheCapabilityDiscoverySource` fails on any `src/main` implementer; scripted source is a private test class; ceiling `IMPLEMENTED` (ADR-P8-010) | Relies on a marker-string scan; a differently-phrased implementer could evade it — the architecture review + `DependencyDirectionTest` are the backstop |
| RISK-134 | A partial pass reads as a complete one (or the reverse), hiding lost discovery work | Med / High | `CapabilitySnapshot.init` refuses `COMPLETE`+failures and `PARTIALLY_COMPLETE`+no-failures; `FAILED` distinguished from both; `DiscoveryStateTest` locks completion-only-through-`DISCOVERING` and terminal non-revival | The three-way rule keys on "was anything established"; a protocol that legitimately reports zero attemptable features yields a `COMPLETE` empty snapshot, which a naive UI could mistake for "supports nothing" |
| RISK-135 | A cancelled pass invents results or loses gathered evidence | Low / High | `Cancelled` returns immediately with prior readings preserved and nothing after invented; `.cancellationEndsThePassAndPreservesEverythingGatheredBeforeIt` | Evidence gathered is retained but the pass is not mergeable (`producedEvidence(CANCELLED) == false`); a caller must decide whether to keep partial work |
| RISK-136 | Time is read directly, breaking testability and Multiplatform support | Med / Med | Only the injected `TimeProvider` is used; `discoveredAtEpochMillis` is null without one; `.aMissingClockYieldsNoTimestampRatherThanAnInventedOne` + `PhaseEightScopeTest.theCapabilityAreaReadsNoWallClockOrAndroidClass` + `DependencyDirectionTest` JVM-import ban | The engine takes `time` optionally; a production wiring must supply the platform clock — none is bound yet |
| RISK-137 | Phase 8's empty/`UNKNOWN` behaviour is mistaken for a broken framework and filled with invented capabilities | High / High | ADR-P8-010 states emptiness as the decision (ADR-P1-013/5-006/7-010 precedent); the engine establishes nothing without a source; `anEmptyAttemptableSetIsACompletePassThatClaimsNothing` | The guard proves the default is empty, not that a future registered protocol's claims are real — evidence review stays human |
| RISK-138 | No hardware claim because JVM tests pass | High / Med | Standing directive + TST-HW-003 cap everything at `IMPLEMENTED`/`LAB_TESTED`; device discovery is `NOT RUN`; the empty source means no capability is claimed for any device | Inherent to a JVM-only, protocol-less phase; closes only in the deferred device session (RISK-097/099/121 continue) |
